# SDK Alignment Analysis: ApiResponse Envelope Integration

## Executive Summary

The InsureTech SDKs (TypeScript and Go) currently **do NOT have a unified ApiResponse<T> envelope wrapper**. Both SDKs handle responses directly without a consistent wrapper, which requires alignment with the new ApiResponse envelope specification.

---

## 1. Current Response Handling

### TypeScript SDK

**Status**: No ApiResponse wrapper currently exists.

- **hey-api client**: Uses `@hey-api/client-fetch` which handles raw HTTP responses
- **Generated files**: 
  - `sdk.gen.ts` - Service method definitions (auto-generated by @hey-api/openapi-ts)
  - `types.gen.ts` - Type definitions (auto-generated)
  - `client-wrapper.ts` - Custom wrapper providing `createInsureTechClient()` for configuration
  
- **Current flow**:
  1. Service methods (e.g., `AiService.aiServiceChat()`) call hey-api client
  2. hey-api handles HTTP request/response
  3. Response is directly unmarshaled to the response type (e.g., `ChatResponse`)
  4. **No envelope unwrapping** - assumes API returns data directly

**Client Wrapper** (`client-wrapper.ts`):
- Creates a configured client with authentication headers
- Does NOT unwrap any envelope - just passes through hey-api's handling
- Example: Sets `Authorization: Bearer ${apiKey}` header
- Does NOT intercept or transform responses

### Go SDK

**Status**: No ApiResponse wrapper currently exists.

- **Client structure**: `pkg/client/client.go`
  - Raw HTTP client with retry logic
  - `DoRequest()` method handles HTTP requests
  
- **Response handling**: 
  ```go
  func (c *Client) DoRequest(ctx context.Context, method, path string, body interface{}, result interface{}) error {
      // ... build request ...
      resp, err := c.httpClient.Do(req)
      // ... check status ...
      if err := json.Unmarshal(respBody, result); err != nil {
          return fmt.Errorf("failed to unmarshal response: %w", err)
      }
      return nil
  }
  ```
  - Directly unmarshals response body to `result` parameter
  - **No envelope unwrapping** - expects data directly

- **Service pattern** (e.g., `AuditService`):
  - Service methods call `c.Client.DoRequest()` with response type
  - Returns `(*models.ResponseType, error)`
  - No envelope processing

## 2. SDK Generation & Post-Processing

### TypeScript Generator (`sdk-generator/typescript/generator.go`)

**What it does**:
1. **Step 1-2**: Installs dependencies and runs @hey-api/openapi-ts
2. **Step 3**: Applies customizations:
   - `customizePackageJson()` - Sets package name, version, adds dependencies
   - `addClientWrapper()` - Creates `client-wrapper.ts` with `createInsureTechClient()`
   - `fixServiceExports()` - Creates `index.ts` that re-exports from `sdk.gen.ts` and `types.gen.ts`
3. **Step 4**: Generates additional files (README, vitest config, prettier config, tsconfig)

**Key insight**: The generator wraps the hey-api output but does NOT add envelope handling logic.

### Go Generator (`sdk-generator/go/generator.go`)

**What it does**:
1. **Parses OpenAPI spec** to extract operations and schemas
2. **Generates models** from OpenAPI schemas with canonical name resolution
3. **Generates services** from OpenAPI paths with metadata
4. **Generates client** with service initialization
5. **Generates go.mod** with module path
6. **Generates README**

**Key insight**: Generates raw service clients that call `DoRequest()` directly without envelope handling.

### Post-Processing Scripts

#### TypeScript (`ts_sdk_correction.py`)

Fixes:
- Class names with colons (`Products:searchService` → `ProductsSearchService`)
- Method names with hyphens (`method-name` → `methodName`)
- Duplicate methods
- HTTP client types
- Enum conflicts
- Service index imports with colons

**Does NOT add envelope unwrapping logic**.

#### Go (`go_sdk_correction.py`)

Fixes:
- go.work interference
- Module path validation
- Runs `go fmt`
- Tests the build

**Does NOT add envelope unwrapping logic**.

## 4. What Needs to Change for ApiResponse Alignment

### TypeScript SDK Changes Needed

1. **Add ApiResponse wrapper type** in `types.gen.ts` or new `types/response.ts`:
   ```typescript
   export interface ApiResponse<T> {
     success: boolean;
     data: T;
     message?: string;
     error?: ApiError;
     timestamp?: string;
   }
   ```

2. **Create response interceptor/transformer** in hey-api client:
   - Hook into hey-api's middleware to unwrap envelopes
   - Transform raw responses to unwrapped data

3. **Update client-wrapper.ts**:
   - Configure hey-api to use response transformer
   - Ensure all service methods return unwrapped data

4. **Update service method signatures**:
   - Services currently expect unwrapped response type
   - May need to accept `ApiResponse<T>` and return `T`
   - OR configure at client level to auto-unwrap

5. **Update TypeScript tests and examples**:
   - Reflect new envelope handling

### Go SDK Changes Needed

1. **Add ApiResponse wrapper type** in `pkg/models/response.go`:
   ```go
   type ApiResponse[T any] struct {
       Success   bool        `json:"success"`
       Data      T           `json:"data"`
       Message   string      `json:"message,omitempty"`
       Error     *ApiError   `json:"error,omitempty"`
       Timestamp string      `json:"timestamp,omitempty"`
   }
   ```

2. **Update DoRequest() method** in `pkg/client/client.go`:
   - Accept response wrapper type
   - Unwrap envelope and return data or error
   - Pattern:
     ```go
     func (c *Client) DoRequest[T any](ctx context.Context, method, path string, body interface{}, result *T) error {
         var resp ApiResponse[T]
         // ... unmarshal response into resp ...
         if !resp.Success {
             return fmt.Errorf("API error: %v", resp.Error)
         }
         *result = resp.Data
         return nil
     }
     ```

3. **Update service methods**:
   - Already accept result parameter, just need updated DoRequest signature
   - No change needed at service level if DoRequest handles unwrapping

4. **Add error handling**:
   - Map `ApiResponse.Error` to Go error types
   - Create `ApiError` type matching backend specification

5. **Update Go tests**:
   - Reflect new envelope handling

## 8. Backward Compatibility Considerations

1. **TypeScript**:
   - Adding response transformer should be transparent to consumers
   - Service method signatures may remain unchanged
   - Consider deprecation path if API currently doesn't use envelope

2. **Go**:
   - Changing `DoRequest()` signature requires major version bump
   - Consider adding new method `DoRequestWithEnvelope()` for gradual migration
   - Or use interface pattern to maintain compatibility

## Conclusion

Both SDKs currently expect API responses without an envelope wrapper. Aligning them with the new ApiResponse envelope requires:

1. **TypeScript**: Adding a response transformer to the hey-api client configuration
2. **Go**: Updating the core DoRequest() method to unwrap envelopes
3. **Both**: Adding ApiResponse/ApiError types to type definitions
4. **Generators**: Updating templates to include envelope handling
5. **Post-processors**: Adding validation for envelope implementation

The changes are focused on the response handling layer with minimal impact on service method signatures and consumer code.
